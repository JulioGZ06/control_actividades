# Parte_4
**1. Explica la diferencia entre Git y GitHub.**

Git sirve para guardar los cambios que hacemos en un proyecto y llevar un historial de ellos. GitHub sirve para subir nuestros proyectos a internet y poder compartirlos con otras personas.

**2. Explica para qué sirve .gitignore.**

Sirve para indicar qué archivos o carpetas no queremos subir a GitHub, por ejemplo, archivos temporales o carpetas que no son necesarias para compartir el proyecto.

**3. Explica por qué .venv no debe almacenarse normalmente en GitHub.**

Porque contiene las librerías que necesita Python para funcionar en nuestro proyecto y puede ocupar mucho espacio. Es mejor crear el entorno virtual en cada computadora e instalar las librerías necesarias.

**4. Explica para qué sirve requirements.txt.**

Sirve para guardar una lista de las librerías que utiliza nuestro proyecto. Así, si otra persona quiere usarlo en su computadora, puede instalar las mismas dependencias fácilmente.

**5. Explica la diferencia entre Stage, Commit y Push.**

Stage es seleccionar los archivos que queremos guardar, Commit es registrar esos cambios en nuestro repositorio local y Push es subir los cambios a GitHub.

**6. Explica por qué un repositorio puede tener varios commits antes de realizar un push.**

Porque podemos ir guardando los avances de nuestro proyecto poco a poco con varios commits sin subirlos todavía a GitHub. Cuando terminemos, podemos hacer un push para enviar todos esos cambios.
